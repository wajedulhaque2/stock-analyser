Current numeric sources are Yahoo price/history/info/fast-info/statements/analyst estimate tables/targets/valuation measures and ^TNX; Fiscal standardized/as-reported statements, ratios, shares, peers, KPIs, and transcript-derived guidance; SEC actuals/filings; user assumption overrides; and analytical/sector fallbacks. Ollama receives selected evidence/context but must remain outside calculations.

## Technical debt and risks

- Provider-shaped dicts and pandas frames cross all layers; period/type/currency/provenance are implicit or string-based.
- `app.py` is a 1,200-line monolith coupling data access, cache, calculations, overrides, and presentation.
- Two DCF generations coexist; automatic forecasts and sector defaults remain central.
- Non-USD cash flows can use US ^TNX, a hard-coded ERP, beta fallback, credit spread, WACC floor, and silent default values.
- Yahoo remains a broad fundamental/consensus source and fallback; Fiscal parsing is tolerant but loses canonical semantics.
- Transcript-extracted management guidance can feed numeric assumptions.
- Current history uses mostly medians without explicit 3/5/10-year windows or robust sample contracts; peers lack full eligibility filtering.
- Share, debt, market cap, and currency reconciliation uses heuristic dict logic. ADR support is absent.
- Confidence is a broad score rather than concrete v1 data coverage; status strings are not typed domain results.
- Cache is primarily Streamlit/session memory; no persistent schema-versioned provider cache, shared capability registry, or uniform 429/backoff layer.
- Tests strongly characterize legacy auto forecasting; V1 synthetic suites now cover providers through FRED/Alpha, canonical observations, reference exclusion, capability failures, bounded period semantics, deterministic pairwise reconciliation, transparent evidence coverage, and an isolated opt-in live contract harness through Milestone 6C.
- Existing tests contain META-like and sector-shaped cases; production audit found no literal ticker branch, but add an enforcement test.

Major migration risks are accidental UI/output changes during strangling, dual-path divergence, provider fiscal-calendar mismatch, unit/currency/ADR errors, licensing leakage through caches/fixtures, rate-limit amplification on Streamlit reruns, treating generic FCF as FCFF, double-counting methods that share the same consensus denominator, and prematurely aggregating sparse/conflicting methods.
