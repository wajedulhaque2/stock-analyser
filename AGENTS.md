# Stock Analyser Engineering Rules

These rules apply to the entire repository. Read the v1 documents in `docs/` before changing data, valuation, or UI code.

## Non-negotiable rules

1. Never add ticker-specific behavior. Company behavior must follow canonical metadata, financial data, industry classification, or an explicitly configured valuation family.
2. Never invent a forecast when reliable sourced consensus exists.
3. Represent missing data with the correct layer-specific status; never fabricate fallback observations. Do not interchange `DataAvailability`, `CapabilityStatus`, `ValuationMethodStatus`, `AggregationStatus`, `CoverageLevel`, or `IssueSeverity`.
4. Every numeric valuation input must carry provenance.
5. Never implicitly mix actual and estimate, annual and quarterly, LTM and NTM, FY1 and FY2, or flow and point-in-time observations.
6. Every monetary observation must carry currency, unit, period, and source.
7. Keep provider field names inside provider adapters. Valuation code consumes canonical domain models only.
8. FMP standard DCF and external analyst price targets are reference-only and must have zero weight in central fair value.
9. Never print, log, commit, document, or place API keys in fixtures. Do not commit raw proprietary responses or caches. Use synthetic fixtures.
10. Every bug fix requires a regression test.
11. Unsupported valuation methods return a structured unavailable result with a reason.
12. Do not silently clamp invalid assumptions or replace missing values with sector assumptions. Validation must expose the issue and fail closed where necessary.
13. Sector awareness determines eligible valuation methods; it must not fabricate future operating performance.
14. Do not use provider `FCF` in a DCF until its economic definition is documented and mapped to FCFF or FCFE with a consistent discount rate and bridge.
15. Do not silently use a US risk-free rate for non-USD cash flows. Withhold the DCF or require an explicit, provenance-bearing override.
16. Do not average providers to manufacture consensus. Select a canonical provider, use others as validators, and surface disagreement.
17. NTM means the next four appropriate fiscal quarters. An annual FY1 value remains labeled FY1.
18. Withhold central fair value when coverage is insufficient, fewer than two independent methods are credible, or method dispersion is excessive.
19. Keep fundamental quality, valuation, estimate momentum, and market behavior separate. Investment stance may use valuation only when valuation is resolved.
20. Ollama is evidence interpretation only and must never generate or alter numeric valuation inputs or outputs.
21. The traded security and issuer/underlying security are separate identities. ADR ratios must be explicit and positive when present.
22. `retrieved_at` and `as_of_at` are distinct. Any substitution of retrieval time for an unavailable source as-of time must be explicit in provenance.
23. `operating_income` and `EBIT` are distinct canonical metrics. Map one provider value to both only when its definition supports that mapping and provenance records it.
24. `ExternalValuationReference` is structurally separate from internal `ValuationResult` and must never enter an internal valuation-result collection.
25. An estimate-endpoint row is forward only when its fiscal period, observation type, and as-of time establish that it is forward; endpoint origin alone is insufficient.
26. V1 provider code uses controlled `ProviderId` values and endpoint-level capabilities; one endpoint failure must never invalidate unrelated capabilities.
27. Provider diagnostics, exceptions, request identities, and cache keys must exclude authentication material and proprietary response bodies. Sanitize URLs and headers before diagnostic use.
28. Generic transport must not classify HTTP 403 as entitlement. Only a provider adapter with provider-specific evidence may translate a failure to `ENTITLEMENT`/`LOCKED`.
29. Provider retries are bounded and policy-driven. Retry only configured timeouts, transient connection failures, HTTP 429, and HTTP 5xx; respect capped `Retry-After` and never sleep in unit tests.
30. V1 cache keys must be deterministic, schema-versioned, parameter-order independent, and secret independent. Expired entries are never returned as fresh.
31. V1 adapters may cache normalized/canonical outputs only. Raw proprietary provider responses must never become cache values, fixtures, diagnostics, exceptions, or documentation.
32. Provider low/average/high estimates are consensus range cases, not coherent bear/base/bull scenarios. Analyst counts apply only to metrics for which the provider explicitly supplies that count.
33. Cash-flow definition eligibility is machine-readable: generic provider FCF remains `provider_defined_fcf` unless verified evidence explicitly establishes FCFF, FCFE, or OCF-less-CapEx economics.
34. Macro selection uses the latest valid observation on or before the requested as-of date. FRED DGS10 is a decimal USD Treasury-yield input only; it is never a non-USD fallback or a WACC calculation.
35. Provider symbols are lookup/audit metadata, never cross-provider match keys. Reconciliation uses stable canonical security and issuer identity plus aligned observation semantics.
36. Reconciliation never mutates, replaces, or averages the canonical observation. Each validator produces an independent comparison record.
37. Reconciliation compares only observations eligible at `comparison_as_of`; retrieval time remains audit metadata. Any maximum as-of gap must be explicit named configuration.
38. Relative difference is `abs(validator - canonical) / abs(canonical)` when canonical is nonzero. Zero-versus-zero is exact; zero-versus-nonzero is an explicit conflict with no relative percentage.
39. Coverage breadth, evidence confidence, and valuation-family readiness are separate controlled types. Never collapse them into one score or infer a monetary result or stance from them.
40. Coverage is evaluated against an explicit aware `analysis_as_of`; exclude later evidence and never consult wall-clock time inside the service.
41. Missing/locked validators are absence states, not conflicts. Preserve dimension granularity: only configured critical conflicts may block or sharply downgrade the whole snapshot.
42. Provider-defined FCF, OCF, and CapEx do not create cash-flow readiness without linked verified FCFF/FCFE economics. Even verified cash flows remain at most partial until discount-rate and bridge machinery exists.
43. Peer and historical-valuation coverage remain `NOT_EVALUATED` until their V1 services exist. Never fabricate readiness from provider availability alone.
44. Live provider verification is explicit CLI-only work. Keep credentials and raw payloads in memory, emit only allowlisted normalized summaries, and convert every confirmed live schema mismatch into a fictitious synthetic adapter regression.
45. Historical valuation evidence uses `HistoricalValuationObservation`; every record has a controlled multiple type, equity/enterprise basis, denominator definition, sampling basis, canonical security/issuer identity, dated provenance, and explicit future-distribution eligibility.
46. Fiscal P/E means its documented share-price/diluted-EPS ratio; Fiscal EV/EBIT uses the provider's documented Operating Profit denominator. Do not generalize that provider-specific ratio definition into `operating_income == EBIT` elsewhere.
47. Preserve finite historical multiple outliers unchanged. Non-positive multiples are ineligible, non-finite values fail closed, and P/FCF or EV/FCF remains withheld until cash-flow economics are verified. Distribution windows and fair-value application require later authorized milestones.
48. Historical distributions use one explicit `HistoricalWindow` at a time: 3Y, 5Y, or 10Y, with 5Y as policy default. Boundaries are inclusive calendar-year offsets from aware `analysis_as_of`; never blend windows or silently fall back to a shorter one.
49. Historical quantiles use documented Type-7 linear interpolation. The default distribution sample is never winsorized, trimmed, clipped, sigma/IQR-filtered, interpolated, cycle-adjusted, or sector-adjusted.
50. Daily Fiscal ratios are serially dependent market observations, not independent fundamental regimes. Preserve daily sampling, expose calendar-month coverage if useful, and keep independent regime count unknown while denominator period ends are unavailable.
51. Historical distributions require centralized count and span thresholds. Identical semantic-date duplicates count once; conflicting duplicates fail closed; provider samples are never combined. A usable distribution still cannot make own-history valuation fully ready before the authorized forward-application milestone.
52. Historical-to-forward denominator compatibility is a controlled decision, not a name match. Fiscal diluted EPS does not equal FMP generic EPS by default, and Fiscal Operating Profit does not equal generic EBIT by default; explicit semantic evidence is required to verify either pairing.
53. Own-history forward selection is one explicit FY1 or FY2 annual estimate case. Default preparation uses FY1 `AVERAGE`; FY1 is never NTM, and low/high analyst ranges are never relabeled as valuation scenarios.
54. Missing cash, gross debt, or a suitable explicit share count is never zero-filled. Net debt may be derived only from compatible currency-matched cash and debt with provenance to both; no implicit FX, share-basis substitution, or ADR conversion is allowed.
55. Milestone 7C method readiness is a non-valuing prerequisite contract. `READY`, `PARTIAL`, and `NOT_READY` do not authorize multiple application, fair value, target price, aggregation, stance, or UI output; those remain deferred.
56. A direct enterprise-to-equity bridge uses same-identity Fiscal `calculated_tev - calculated_market_cap` observations only. Require compatible dates/currency and explicit suitable current-share semantics; never combine providers, zero-fill components, average bridge methods, invent FX/ADR conversion, or treat readiness as valuation.
57. Milestone 7D own-history valuation applies P25, median, and P75 from exactly one selected usable window to the same selected `AVERAGE` FY denominator. Calculate one method independently, use exactly the bridge/share evidence named by `READY`, fail non-positive denominators/equity points closed without floors, and never introduce analyst scenarios, provider scaling, current price, aggregation, stance, or UI behavior.
58. Milestone 7D.1 orchestration resolves canonical identity, composes the existing 7A-7D services, and executes only individually `READY` methods. Live valuation audit is explicit CLI-only, uses one window and one FY `AVERAGE` denominator, independently reconstructs every valid point, and never fetches a market snapshot or adds current-price comparison, method aggregation, stance, ticker branches, provider scaling, or UI wiring.
59. Milestone 7E portability validation treats correct `PARTIAL`, `NOT_READY`, and `UNAVAILABLE` outcomes as successful fail-closed audits. Preserve canonical listing suffixes, allow explicitly resolved provider symbols to differ, distinguish reporting currency from quote currency/unit, never convert GBP/share to GBp/share inside valuation, and never add ticker, sector, FX, macro, outlier-cap, window-switch, ranking, aggregation, price-comparison, or UI behavior to force cross-stock results.
60. Milestone 8A provider peers are candidates only. Resolve canonical security and issuer identity before selection; remove self references and duplicate issuers by canonical issuer ID; require eligible listed equity, controlled industry evidence, visible financial/readiness criteria, and at least three independent included issuers for `USABLE`. Provider rank/agreement are provenance only. Never invent business-model labels, compare cross-currency absolute scale without FX, create an opaque peer score, calculate a peer multiple/fair value, consume own-history distributions, or add ticker/UI behavior.
61. Milestone 8A.1 distinguishes summary-seeded identity, optional profile enrichment, economic peer membership, and EV/EBITDA method-data readiness. Stable provider issuer/security IDs plus required listing evidence seed identity; security eligibility follows the superseding 8A.2 rule below. Name/ticker/reasoning alone may not seed identity. Canonical actuals deduplicate exact compatible evidence and use only verified source/revision chronology for conflicts—never retrieval order, averaging, or SEC replacement. Missing forward EBITDA must not change economic membership. A provider-specific symbol is never copied across providers without stable verified cross-provider identity.
62. Milestone 8A.2 separates canonical peer identity from security eligibility. Stable Fiscal company/security IDs plus primary listing ticker/exchange may establish identity without security type; missing or incompatible security-class evidence leaves eligibility and economic selection `UNVERIFIED`, not identity unavailable. `companyType=operating_company`, name, relationship, reasoning, or ticker never proves common equity. Full profile and listing-compatible Yahoo metadata are optional classification enrichment and may not redefine Fiscal-anchored identity.
63. Milestone 8A.3 resolves Fiscal peer financial access only through same-record stable `companyFiscalIdentifier` evidence to opaque `companyKey` metadata. Never join peer financials by ticker or name, expose `companyKey` as canonical identity, infer currency, fabricate EBITDA, weaken `select_canonical_actual`, or let financial evidence bypass security/industry gates. Economic membership remains independent of FMP method readiness and still requires three independent included issuers for `USABLE`.
64. Milestone 8A.4 binds standardized financial statements at issuer level through the verified Fiscal issuer-to-companyKey relationship. Representative security ID and provider symbol remain identity/provenance evidence but are not issuer-statement equality gates. Target and peer use the same request/parser; explicit row currency precedes verified cached/profile reporting currency, and no USD default exists. Provider HTTP absence stays endpoint-isolated and never erases peer identity or authorizes ticker fallback.
65. Milestone 8B treats 8A economic membership as immutable outer-gate input. Only `INCLUDED` issuers may contribute one EV/EBITDA observation, using same-peer positive base-unit point-in-time EV and stable-identity-bound annual FMP `AVERAGE` FY1/FY2 EBITDA with matching currency and eligible dates. Require three independent valid issuers for a usable subset. Never join by ticker/name, use NTM or low/high, apply FX/provider scaling, clip observations, calculate a peer distribution/target value, consume own-history evidence, or wire UI behavior.
66. Milestone 8C consumes exactly one canonical 8B `PeerValuationSubset` and its observations. Use explicit Type-7 P25/median/P75 with median as the central statistic, retain every finite positive valid ratio without automatic removal, and require three independent issuers for a usable distribution. Different peer fiscal period ends and underlying currencies are allowed under one FY policy because the outputs are dimensionless. Never refetch providers, alter economic membership, invent dispersion thresholds, or consume target EBITDA/capital bridge/current price/own-history evidence; target application is deferred to 8D.
67. Milestone 8D applies only one `USABLE` 8C EV/EBITDA distribution to the same target's aligned annual `AVERAGE` FY1/FY2 EBITDA. Lower/central/upper use peer P25/median/P75 against the same denominator, subtract exactly one approved direct or component enterprise adjustment, and divide by the exact approved shares. Preserve base currency (including GBP/share), fail closed on identity/period/currency/bridge/share defects, and retain non-positive equity traces without flooring. Never consume current price, external targets/DCF, own-history output, aggregation, stance, provider scaling, or UI state.
68. Milestone 8E coordinates the existing 8A–8D peer services without replacing their rules. Preserve the earliest controlled failure stage and treat expected unavailable as a successful fail-closed audit outcome. Cross-stock audits use the same explicit opt-in code, preserve canonical symbols, stable provider identity, issuer-specific fiscal calendars, reporting/quote currency and quote-unit distinctions, and no automatic outlier removal. Never add ticker/sector branches, manual peers, symbol rewrites, implicit FX or GBP/GBp conversion, current-price interpretation, own-history combination, family aggregation, stance, or UI wiring.
69. Milestone 9A makes discount-rate evidence follow modeled cash-flow currency. FRED DGS10 is USD-only and uses the latest non-future observation under one centralized freshness policy; never interpolate it, convert it through FX, or use it for non-USD cash flows. Require explicit provenance-bearing ERP, preserve undocumented provider beta as `PROVIDER_DEFINED` and ineligible by default, calculate only exact CAPM when inputs are eligible, and report WACC prerequisites without manufacturing debt cost, tax, debt market value, WACC, DCF, reverse DCF, current-price output, aggregation, stance, or UI behavior.
70. Milestone 9B.1 selects only the dated NYU Stern US implied ERP trailing-12-month adjusted-payout series under a centralized 62-day policy and pairs it with full observed DGS10. Canonical beta is 5Y/60 monthly simple total returns for target versus the controlled SPY adjusted-return benchmark, OLS with intercept, minimum 36 aligned returns, and no interpolation, forward-fill, weekly fallback, provider-beta averaging, Blume/shrinkage, leverage/industry adjustment, or cap. Non-positive beta is ineligible by default. A ready CAPM cost of equity does not authorize production WACC, DCF, reverse DCF, current-price interpretation, aggregation, stance, or UI wiring.
71. Milestone 9B.2 permits USD WACC only for explicitly scoped large US non-financial operating companies when every input is eligible. Equity is canonical market cap; debt is gross debt and may remain visibly `BOOK_VALUE_PROXY` under the explicit policy; synthetic debt cost uses same-period annual EBIT/interest-expense magnitude plus the sourced NYU large-non-financial rating band and DGS10; tax is domicile-selected sourced marginal tax. Missing claims are never zero, and nonzero or unavailable TEV residual treatment blocks standard WACC. Never use net debt as a weight, effective tax as marginal tax, interpolate spreads, add premiums, round calculations, or begin DCF/reverse DCF/current-price/UI work.
72. Milestone 9B.3 uses Fiscal's documented period-based `/v1/company/ratios` boundary for `calculated_total_debt`, `calculated_net_debt`, and the provider coverage-ratio validator. Debt and net debt remain distinct point-in-time actuals; the coverage ratio never substitutes for its underlying annual numerator and interest expense. Company-class scope requires canonical US domicile, non-financial sector/industry, `operating_company` type, eligible USD market cap at or above the sourced USD 5 billion threshold, and no ticker inference. Missing or conflicting evidence fails closed; preferred/NCI remain unresolved unless directly sourced or the aligned TEV residual is exactly zero.
73. Milestone 10A makes reverse DCF an enterprise expectations-readiness family, not a forecast or valuation engine. Use canonical annual FMP `AVERAGE` revenue/EBIT only, preserve fiscal periods and gaps, and derive only aligned EBIT margin and consecutive revenue growth. Canonical Fiscal actuals anchor FY1 growth only for the exact preceding fiscal year; `OPERATING_INCOME` never becomes EBIT. ## Change discipline

- Preserve existing behavior unless a task explicitly authorizes a behavior change.
- Migrate incrementally behind characterization and regression tests; do not perform a blind directory rewrite.
- Add provider calls only after capability detection, caching, timeout/retry/429 handling, and failure isolation are designed.
- Do not make live API calls in unit or regression tests. Keep live smoke tests explicit, opt-in, secret-safe, and excluded from normal CI.
- Maintain provenance through ingestion, normalization, reconciliation, valuation, aggregation, and presentation.
- Provider adapters interpret payloads; generic transport retrieves them and must not create financial domain observations.
- Domain code must never import provider infrastructure, and legacy UI/valuation code must not import V1 provider DTOs until an approved migration milestone.
